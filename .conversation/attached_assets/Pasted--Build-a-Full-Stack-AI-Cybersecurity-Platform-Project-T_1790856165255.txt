# Build a Full-Stack AI Cybersecurity Platform

## Project Title

**Cybersecurity Log Anomaly Detection System**

Build a professional, production-style web application called:

# **CyberGuard AI**

Subtitle:

**AI-Powered Cybersecurity Log Anomaly Detection & Endpoint Security Platform**

This is an M.Tech AI/ML project. The application must demonstrate meaningful Machine Learning, Deep Learning, Explainable AI, cybersecurity log analysis, endpoint monitoring, anomaly detection, and an AI security assistant.

Do NOT create a fake/static demo. Build a functional application with real backend APIs, database models, ML/DL pipelines, realistic sample data, and clear separation between frontend, backend, ML services, and endpoint-agent functionality.

---

# PHASE 1 — TECHNOLOGY STACK

Use:

### Frontend

* React
* TypeScript
* Tailwind CSS
* shadcn/ui or another clean component system
* Recharts or equivalent charting library
* Responsive desktop-first cybersecurity dashboard

### Backend

* Python
* FastAPI
* REST APIs
* Pydantic
* SQLAlchemy

### Database

Use PostgreSQL where available.

For local/demo development, provide a SQLite fallback if PostgreSQL is unavailable.

### Machine Learning

* scikit-learn
* XGBoost
* pandas
* NumPy
* imbalanced-learn
* SHAP

### Deep Learning

* TensorFlow
* Keras

### Security

* Password hashing
* JWT/session authentication
* HTTPS-ready API design
* Input validation
* Rate limiting
* CORS configuration
* Never expose secrets/API keys in frontend code

### Endpoint Agent

Create a separate Python module/application that can run on Windows.

It should collect only explicitly configured/authorized telemetry and logs.

# PHASE 12 — DEEP LEARNING AUTOENCODER

Build a TensorFlow/Keras autoencoder.

Architecture:

```text
Input
 ↓
Dense
 ↓
Dense
 ↓
Latent Representation
 ↓
Dense
 ↓
Dense
 ↓
Reconstruction
```

Train primarily on normal behavior when appropriate.

Calculate reconstruction error.

Use:

```text
low reconstruction error → normal-like
high reconstruction error → anomaly candidate
```

Do not claim that reconstruction error alone proves malicious activity.

Display:

* Reconstruction error
* Threshold
* Anomaly status

15. Receive security alerts.
16. Visualize anomalies and attacks.
17. Ask the AI Security Assistant questions about actual findings.
18. Investigate individual events.
19. Generate a security report.
20. Train and compare models.
21. View model performance.
22. Manage connected devices.

The final product should feel like a **miniature AI-powered Security Operations Center (SOC) platform**, while remaining an academically defensible M.Tech ML/DL project.

# FINAL RULE

Prioritize correctness and functionality over adding fake features.

If a feature cannot safely or reliably be implemented in a browser, implement it through the authorized endpoint agent and communicate with the backend through authenticated APIs.

Never provide unrestricted remote shell execution, arbitrary destructive commands, silent surveillance, or automatic file deletion/quarantine.

Build the project incrementally and ensure every phase runs before moving to the next phase.
